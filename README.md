# tvtrim

电视剧剧集**批量去头去尾**工具,Go 实现,基于 [ffmpeg-trim](https://github.com/totootao/ffmpeg-trim)。

砍掉每集固定的片头曲和片尾曲时长,**零重编码** —— 只做 stream copy,速度接近磁盘拷贝。

```console
$ tvtrim -auto -dry-run ./某剧第一季/

tvtrim 1.5.0
  模式    : 自动识别片头/片尾(静音检测)
  ffmpeg  : /root/.cache/tvtrim/ffmpeg-linux-amd64
  待处理  : 24 个文件 / 1 部剧
  输出方式: 同目录生成,后缀 "-trim"
  模式    : 预览(dry-run)

自动识别结果(静音阈值 -35dB, 切点静音 ≥0.8s):

  剧集                   文件                         -head     -tail  说明
  ----------------------------------------------------------------------------------------------------
  某剧                      /剧/EP01.mkv              42.0s      45.0s  [一致 24/24] 片头切点 42.0s,片尾切点 1185.0s(ED 88s)
  ...
```

---

## 特性

- **零重编码**:`-c copy` 原样搬运数据,不损失画质,速度极快
- **自动识别片头片尾**:`-auto` 基于静音检测定位 OP/ED 边界,多集结果自动众数纠错;
  默认**每部剧只抽样前 3 集**检测再把结论套用全剧,不必每集都解码
- **识别结果会记住**:切点写进缓存文件,下次只识别**新增/变动**的集,
  已经识别过的直接沿用(24 集实测 0.89s → 0.03s)
- **Web 人工确认**:`-web` 扫描后在浏览器里逐集查看/微调切点,按剧勾选确认才真正执行
- **一个目录多部剧**:按文件名/目录名自动推断剧名并分组,各剧**独立**纠错、独立确认,互不干扰
- **批量处理**:给一个目录就自动扫出所有剧集,并发处理
- **集数识别**:自动解析 `S01E02` / `第02集` / `EP02` 等命名并按剧按集排序
- **mp4 快速起播**:输出自动加 `-movflags +faststart`(moov 移到文件头)
- **安全默认**:默认生成新文件不碰原片,输出时长过短自动跳过,重复运行拒绝覆盖;
  空输出检测兜底,不产生"看似成功实为空文件"的垃圾
- **原地替换**:`-inplace` 先写临时文件再原子替换,中途失败不会损坏原片
- **ffmpeg 自动获取**:首次运行自动从 ffmpeg-trim 下载对应架构的二进制并校验;
  上游更新后缓存版本不符会**自动重新下载**,无需手动清理
- **零第三方依赖**:只用 Go 标准库

## 安装

```sh
# 从源码编译(需要 Go 1.21+)
git clone https://github.com/totootao/tvtrim.git
cd tvtrim
go build -o tvtrim ./cmd/tvtrim
```

也可以直接用 `go install`:

```sh
go install github.com/totootao/tvtrim/cmd/tvtrim@latest
```

### Docker

镜像 `totootao/tvtrim` 由 GitHub Actions 自动构建并推送到 Docker Hub,
支持 `linux/amd64` 与 `linux/arm64`,**镜像内已预置 ffmpeg-trim**,无需运行时下载:

```sh
docker pull totootao/tvtrim

# 裁剪宿机当前目录下的剧集(注意用绝对路径挂载)
docker run --rm -v "$PWD/某剧.S01":/media totootao/tvtrim -auto /media

# 与宿机的 uid/gid 对齐,避免输出文件变成 root 所有
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/某剧.S01":/media \
  totootao/tvtrim -head 90 -tail 60 /media

# Web 界面:容器里自动监听 0.0.0.0:8080,不用再手写 -addr
docker run --rm -p 8080:8080 --user "$(id -u):$(id -g)" -v "$PWD/某剧":/media \
  totootao/tvtrim -web -auto /media
```

容器默认工作目录 `/media`,入口就是 `tvtrim`,所以镜像名之后的参数与命令行版一致。

`-web` 在容器内会自动监听 `0.0.0.0:8080`(宿机上仍是安全的
`127.0.0.1:随机端口`),并且不会尝试启动浏览器 —— 上面的 `-p 8080:8080`
加上之后浏览器打开 `http://localhost:8080/` 即可。`-addr` 仍然优先于这个默认值。

容器里的识别缓存默认写在 **`/media/.tvtrim-cache.json`**,也就是你挂载进来的
那个目录 —— 这样即便 `docker run --rm` 每次都是全新容器,下次也能直接沿用上次的
识别结论(想换位置用 `-cache-file` 或 `TVTRIM_CACHE_FILE`)。

| 镜像标签 | 含义 |
|---|---|
| `totootao/tvtrim:latest` | main 分支最新构建 |
| `totootao/tvtrim:main` | 同上(buildx 分支标签) |
| `totootao/tvtrim:1.5` / `:1.5.0` | 对应 `v*` tag 发布的版本 |

## 用法

```sh
tvtrim [选项] <文件或目录> [更多文件或目录...]
```

### 常用示例

```sh
# 砍掉 90 秒片头 + 60 秒片尾,输出 xxx-trim.mp4
tvtrim -head 90 -tail 60 ./某剧.S01/

# 自动识别每集的片头曲/片尾曲(推荐先 dry-run 看识别结果)
tvtrim -auto ./某剧.S01/ -dry-run

# 打开 Web 界面:识别后在页面上逐剧确认,点"确认执行本剧"才真正裁剪
tvtrim -web -auto -r ./某剧全集/

# Web 界面 + 手动时长(页面上仍可逐集微调 head/tail)
tvtrim -web -head 90 -tail 60 ./某剧.S01/

# 先预览会做什么,不动文件
tvtrim -head 1m30s -tail 45s ./某剧.S01/ -dry-run

# 递归处理整个剧集目录
tvtrim -r -head 90s -tail 60s ./某剧全集/

# 直接替换原文件(自动开启 -overwrite,建议先备份)
tvtrim -head 90s -tail 60s -inplace ./某剧.S01/

# 指定输出到单独目录(仅单文件)
tvtrim -head 90s -tail 60s -o ./out/ep01.mp4 ./in/ep01.mkv

# 提高并发(机械硬盘建议 1-2,SSD 可用默认值)
tvtrim -head 90s -tail 60s -j 4 ./某剧.S01/
```

### 全部选项

| 选项 | 说明 | 默认值 |
|---|---|---|
| `-auto` | 自动识别片头/片尾(与 `-head`/`-tail` 互斥) | 关闭 |
| `-web` | 启动 Web 界面,人工确认后再执行 | 关闭 |
| `-addr <地址>` | Web 监听地址,默认宿机 `127.0.0.1:0`、容器内 `0.0.0.0:8080` | 见左 |
| `-no-open` | `-web` 时不自动打开浏览器(容器内自动不尝试) | 关闭 |
| `-head <时长>` | 要砍掉的片头时长 | — |
| `-tail <时长>` | 要砍掉的片尾时长 | — |
| `-keep <时长>` | 结尾额外保留的安全余量,会让输出更短 | `0` |
| `-suffix <后缀>` | 输出文件名后缀,`a.mp4` → `a-trim.mp4` | `-trim` |
| `-inplace` | 原地替换原文件(先写临时文件再原子替换) | 关闭 |
| `-o <路径>` | 显式指定输出文件(仅单文件) | — |
| `-r` | 递归处理子目录 | 关闭 |
| `-j <数量>` | 并发数 | CPU 核数 |
| `-sample <数量>` | `-auto` 时每部剧抽样几集做静音检测,`0` 表示每集都测 | `3` |
| `-cache-file <路径>` | 识别结果的缓存文件位置 | 容器内媒体目录,宿机 `~/.cache` |
| `-no-cache` | 不读写识别缓存(每次都重新识别) | 关闭 |
| `-refresh` | 忽略已有缓存,全部重新识别后覆盖写回 | 关闭 |
| `-dry-run` | 只预览不执行 | 关闭 |
| `-overwrite` | 允许覆盖已存在的输出文件 | 关闭 |
| `-min <时长>` | 输出时长下限,低于此值则跳过 | `10s` |
| `-ffmpeg <路径>` | 指定 ffmpeg 可执行文件 | 自动查找 |
| `-no-download` | 禁止自动下载 ffmpeg-trim | 关闭 |
| `-v` | 输出详细信息 | 关闭 |

### 时长格式

`-head` / `-tail` / `-keep` / `-min` 都支持多种写法:

| 写法 | 含义 |
|---|---|
| `90` | 90 秒 |
| `90s` / `30秒` | 90 秒 / 30 秒 |
| `1m30s` / `1分30秒` | 1 分 30 秒 |
| `1:30` | 1 分 30 秒 |
| `0:01:30` | 1 分 30 秒(时:分:秒) |
| `1h2m3s` / `1小时` | 1 小时 2 分 3 秒 / 1 小时 |
| `1.5s` / `0.5m` | 1.5 秒 / 30 秒 |

### 支持的容器

`mp4` · `mkv` · `ts` · `avi` · `mp3` · `webm` · `asf` / `wmv`

这是 ffmpeg-trim 内置且能正常输出的全部容器。`flv` / `ogg` / `mpg` 可以作为输入
(显式指定文件不受白名单限制),但建议用 `-o` 把输出指定为 `.mkv`:

- `flv`:ffmpeg-trim 未启用 flv1 解码器,探测不出画面宽高,直接输出 flv 会报
  "dimensions not set"
- `ogg` / `mpg`:ffmpeg-trim 未内置对应的输出 muxer

## 工作原理

去头去尾本质是把 `[head, 总时长 - tail]` 这个时间窗口的数据搬运到新文件:

```
原文件:  |==== 片头 ====|======= 正片 =======|==== 片尾 ====|
              head                               tail
裁剪后:                |======= 正片 =======|
```

程序分三步:

1. **探测** —— 用 `ffmpeg -i <file>` 的 stderr 输出解析时长与流信息
   (ffmpeg-trim 裁掉了 ffprobe,只能这样读元数据)
2. **规划** —— 计算窗口 `start=head`、`end=总时长-tail`,并做合法性检查
3. **执行** —— 并发调用 `ffmpeg -i in -ss <start> -to <end> -map 0 -c copy -f <muxer> out`

### 关于切点精度

因为是 stream copy,切点会被对齐到**关键帧**:

- **音频(AAC/MP3)** 精确到音频帧(约 20ms)
- **视频** 只能从关键帧开始,实际切点可能比设定值早/晚一个 GOP(常见 1~5 秒)

对"砍掉固定时长片头曲"这类场景完全够用。如果你需要**帧精确**裁剪,那就必须重编码,
而 ffmpeg-trim 刻意删掉了所有编码器 —— 那属于另一个工具。

> **实测数据**:30 秒测试片砍 5 秒头 + 5 秒尾,输出 20.01 秒;
> 45 秒片砍 10 秒头 + 8 秒尾,输出 27.01 秒。误差在几十毫秒级。
> webm(VP8/Vorbis)与 asf/wmv(WMV2/WMAv2)实测同样精确(40 秒片 → 30.0x 秒)。

### TS 格式特别注意

TS 没有关键帧索引,若起点落在非关键帧且窗口内没有关键帧,**视频轨会被丢弃**(音频不受影响)。
广播流通常 1~5 秒一个 GOP,一般无碍;拿不准就先输出 TS。

## 自动识别片头片尾(-auto)

手动量每集片头片尾很繁琐,`-auto` 用静音检测自动定位切点:

```
原文件:  |静音|== OP ==|静音|====== 正片 ======|静音|== ED ==|静音|
                 ↑切点                          ↑切点
输出:                      |====== 正片 ======|
```

**工作方式**:

1. 对抽样集跑 `silencedetect`(阈值 -35dB,静音 ≥0.8s 计为转场)——
   **默认每部剧只抽前 3 集**,见下方「抽样」
2. 片头切点 = OP 时长窗口(20~210s)内第一个转场静音的结束处
3. 片尾切点 = "正片→ED 的转场静音"起点;若找不到(硬切),退化为只剪 ED 之后的静音
4. **多集众数纠错**:同一部剧每集 OP/ED 时长一致,偏离多数集超过 ±1.5s 的结果
   自动按众数修正(单集误判被消除)。众数按 **剧** 分组计算(见下节),
   不同剧之间不会互相拉平
5. **结论推广**:抽样集的众数值套用到该剧其余未检测的集
6. 裁剪仍走 stream copy,切点对齐关键帧的规则与手动模式一致

**建议流程**:先 `tvtrim -auto ./某剧/ -dry-run` 检查识别表(每集会显示
`[一致 n/m]` 置信度与判定依据),确认无误后去掉 `-dry-run` 执行。

### 抽样:为什么不用每集都测

同一部剧的 OP/ED 时长全剧一致,而 `silencedetect` 要**整片解码音轨**
(这是 `-auto` 唯一的耗时大头)。所以默认每部剧只抽前 3 集:

```console
[####--------------------] 1/24  16%  已用 0.01s  预计剩 0.03s   ← 探测全部(很快)
[########################] 24/24 100%  已用 0.01s
[########----------------] 1/3  33%  已用 0.42s  预计剩 0.83s   ← 只抽 3 集检测
[########################] 3/3 100%  已用 0.55s

  剧集        文件          -head     -tail  说明
  巨人        S01E01.mkv    30.0s      45.0s  [一致 24/24] 片头切点 30.0s,片尾切点 155.0s(ED 20s)
  巨人        S01E02.mkv    30.0s      45.0s  [一致 24/24] 片头切点 30.0s,片尾切点 155.0s(ED 20s)
  巨人        S01E03.mkv    30.0s      45.0s  [一致 24/24] 片头切点 30.0s,片尾切点 155.0s(ED 20s)
  巨人        S01E04.mkv    30.0s      45.0s  [一致 24/24] 沿用本剧 3 集抽样结果(未逐集检测)
  ...
```

**实测 24 集**:`-sample 0`(每集都测)用时 2.5s,默认抽样 0.6s —— 约 **4 倍**
提速,集数越多差距越大。

| 选项 | 行为 |
|---|---|
| `-sample 3`(默认) | 每部剧抽前 3 集,取多数派的结论套用全剧 |
| `-sample 1` | 只测 1 集就套用(最快,但这一集判错全剧跟着错) |
| `-sample 0` | 每集都测(最慢最稳,即 1.4.1 及以前的行为) |

**安全网**:抽样集互相不一致时众数不成立,此时不硬套任何一个值,而是自动
**退回对整部剧全部重测**,并在终端说明:

```console
抽样集结论不一致,改用全部 24 集重新判定(可用 -sample 关闭抽样)
```

`-sample 1` 是例外 —— 只有一个样本时没有第二个结果可比,重测没有意义,
会直接采用这一个结果。

> 每季只有 2 集且互不相同时同样无法判定:结果保留各自的值并标 `[一致 1/2]`,
> 建议在 Web 界面里手动确认其中一集。

### 输出顺序稳定

预览表和汇总表的行顺序**始终跟着输入顺序**,不受并发完成先后影响
(v1.4.2 及以前这两个表每次跑出来的行序都是随机的):

```console
$ tvtrim -auto -dry-run ./某剧/ | sed -n '/自动识别结果/,$p' | md5sum
734a39fd1889307dae9a77ed39a72e12  -     # 连跑几次都一样
$ tvtrim -auto -dry-run ./某剧/ | sed -n '/自动识别结果/,$p' | md5sum
734a39fd1889307dae9a77ed39a72e12  -
```

于是同一条命令重跑可以直接 `diff`,不用担心表格行换来换去。
注意进度条那一小段带计时,每次都不相同 —— 想整段比对时从
`自动识别结果` 那行开始截取即可。

### 缓存:只识别新增的集

同一批文件反复识别纯属浪费 —— 一部剧的 OP/ED 时长不会变,而静音检测要
**整片解码音轨**。所以识别出的切点会写进缓存文件,下次启动时:

- **已记录过且文件没变**的文件直接沿用结论,不再解码;
- **新增的、或被重新压制过的**文件才真正去检测;
- 沿用本剧既有结论的多数派,新增集若偏离也会被拉回本剧的切点。

```console
$ tvtrim -auto -dry-run ./某剧/
识别缓存: /某剧/.tvtrim-cache.json(首次识别 24 个文件)

$ tvtrim -auto -dry-run ./某剧/
识别缓存: /某剧/.tvtrim-cache.json(全部 24 个沿用上次结论,无需重新识别)

# 往目录里再拷两集
$ tvtrim -auto -dry-run ./某剧/
识别缓存: /某剧/.tvtrim-cache.json(24 个沿用上次结论, 2 个新识别)
```

24 集实测:首次 0.89s,全部命中缓存 **0.03s**。表格里沿用缓存的行会标注
`沿用上次识别 · …`,来源一眼可见。

**缓存放在哪**

| 环境 | 默认位置 | 原因 |
|---|---|---|
| 宿机 | `~/.cache/tvtrim/detect.json` | 不往媒体库里塞东西 |
| 容器 | 媒体目录下的 `.tvtrim-cache.json` | `docker run --rm` 每次都是新容器,只有挂载进来的目录能留下来 |

用 `-cache-file` 或环境变量 `TVTRIM_CACHE_FILE` 可以指定别的位置。
缓存文件是点号开头的隐藏文件,Plex/Jellyfin 之类的刮削一般会忽略它。

**失效与刷新**

- 文件的**大小或修改时间**变了 → 当作新文件重新识别(重新压制过不会沿用旧切点)
- 识别参数变了(阈值、抽样数、缓存结构版本)→ 整份缓存失效重算
- `-refresh` 强制全部重测并覆盖写回;`-no-cache` 完全不碰缓存

> 换了季、OP/ED 真的换了,用 `-refresh` 重来一次即可。
> 缓存只记结论不记媒体内容,删掉它不会有任何副作用。

### 多部剧的目录布局

tvtrim 支持三种常见布局,都会**自动拆成不同的剧**分别处理:

```
① 混排在一个目录        /剧集/进击的巨人.S01E01.mkv   /剧集/权力的游戏.S01E01.mkv
② 每剧一个子目录        /剧集/进击的巨人.S01/S01E01.mkv   /剧集/权力的游戏.S01/S01E01.mkv
③ 剧目录 → 季目录 → 集  /剧集/进击的巨人/S01/S01E01.mkv   /剧集/进击的巨人/S02/S02E01.mkv
```

剧名的推断顺序是 **文件名 > 父目录名 > 祖父目录名**:

1. 先剥掉 `[字幕组]`、`(1080p)`、`WEB-DL`、`x264` 之类的标签,取文件名里
   **第一个季集标记之前**的部分(布局 ①)
2. 文件名里没有剧名(如就叫 `S01E01.mkv`)时,用所在**目录名**(布局 ②);
   目录名尾部的 `S01` / `Season 2` / `第2季` 会被剥掉,所以 `进击的巨人.S01`
   和 `进击的巨人` 是同一个剧名
3. 父目录本身是纯季目录(`S01` / `Season 1` / `第1季`)时跳过它,再往上一层
   取剧名(布局 ③),于是第 1 季和第 2 季显示为同一部剧,而不是 `S01` / `S02`

然后按 `(所在目录, 剧名, 季)` 分组:

- **识别表与裁剪表**多一列「剧集」,按剧排序,一眼能看出分了几部
- **众数纠错各剧独立**:巨人的 head 是 30s、权游是 60s,各自向本剧的多数集
  对齐,不会把权游拉成 30s(这是 v1.3 之前的行为,已修正)
- **Web 界面每「剧 + 季」一张表**,可只勾其中一部执行
- 剧名不同写法会自动归并:`The.Show` / `The-Show` / `the_show` / `THE SHOW`
  视为同一部剧

命令行概览行会显示剧数:

```console
  待处理  : 7 个文件 / 2 部剧
```

> 布局 ③ 下 `-r` 是必须的 —— 不加 `-r` 只会扫描指定目录这一层。
> 每季集数少于 3 集时众数纠错可能没有明显多数派(如两集分别是 30s 与 34s,
> 谁都不占多数),这时建议在 Web 界面里手动确认那一集。
```

**已知局限**:

- 美剧 cold open 结构(正片片段→OP)下,"去片头"会连 cold open 一起剪掉
- OP/ED 与正片之间无静音硬切的剧集识别不到对应切点(片尾会退化为只剪 ED 后部分)
- 个别集因误判被众数修正后,切点可能与该集实际转场相差 1~2 秒(与多数集对齐)

## Web 界面(-web)

自动识别再准,也难免有"这一季第二集的 OP 不一样"的情况。`-web` 把扫描/识别结果
铺到浏览器里,**由人按剧确认**后才真正执行:

```sh
tvtrim -web -auto -r ./某剧全集/          # 自动识别 → 页面确认
tvtrim -web -head 90 -tail 60 ./某剧.S01/ # 手动时长 → 页面微调后确认
tvtrim -web -auto -addr 0.0.0.0:8080 ./某剧/  # 指定监听地址(注意安全)
```

容器内运行(Docker / Kubernetes)时无需写 `-addr`:tvtrim 会自动探测并监听
`0.0.0.0:8080`,因为容器的回环地址外部是连不进来的。见下文「监听地址的选择」。

启动后会打印本地地址并尝试自动打开浏览器(`-no-open` 可关掉,容器内自动不尝试):

```console
tvtrim 1.5.0
  待处理  : 7 个文件 / 2 部剧
  正在自动识别切点(7 个文件)…
  识别完成: 7 成功
  Web 界面: http://127.0.0.1:34567/
```

### 页面上能做什么

- **按剧折叠**:分组维度是「文件所在目录 + 剧名 + 季」,每部剧一张表;
  同一个目录里混排的多部剧会拆成多张表;无季号的零散文件单独成组排在最后
- **逐集查看**:文件名、时长、大小、容器、建议 head/tail、识别依据(Note)、是否可执行
- **逐集微调**:直接改某集的 head/tail,实时重算"裁剪后"时长
- **三种执行粒度**:勾选单集 →「执行选中」;一键「选本剧」→「确认执行本剧」
- **实时进度**:执行期间每 700ms 轮询进度,显示已完成/失败、输出体积、耗时
- **退出**:页面上的"退出"按钮与终端 Ctrl+C 都能优雅关闭服务

识别失败的集在页面上**不可勾选**,必须先手动给它填 head/tail。

界面是单个 `embed` 进二进制的 HTML 文件,没有任何外部资源请求,离线可用。

### HTTP API

页面与后端之间只有 4 个 JSON 接口,也可以直接用 curl 驱动(自动化场景很方便):

| 接口 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 页面本身 |
| `/api/state` | GET | 版本、模式、ffmpeg 路径、汇总、剧集列表、当前任务快照 |
| `/api/run` | POST | 提交执行:`{"items":[{"path":"...","head":42,"tail":45}]}` |
| `/api/progress` | GET | 任务进度快照(每集状态 `pending/running/done/failed`) |
| `/api/cancel` | POST | 取消正在执行的任务(已完成的不会被回滚) |
| `/api/shutdown` | POST | 关闭服务并让命令退出 |

示例:只处理指定的两集,并把第二集片头从 42s 改成 10s

```sh
curl -s localhost:34567/api/run -H 'Content-Type: application/json' -d '{
  "items": [
    {"path": "/剧/S01E01.mkv", "head": 42, "tail": 45},
    {"path": "/剧/S01E03.mkv", "head": 10, "tail": 20}
  ]
}'
curl -s localhost:34567/api/progress
```

> 安全提醒:宿机上默认只监听 `127.0.0.1`,用 `-addr 0.0.0.0:...` 对外暴露时任何人都能
> 读写你本机上的媒体文件,请确认网络环境可信。

### 监听地址的选择

`-addr` 留空时按运行环境决定默认值,这样就不用在容器里额外加参数:

| 运行环境 | 默认监听 | 原因 |
|---|---|---|
| 宿机 | `127.0.0.1:随机端口` | 只监听回环,同网段其他人访问不到,最安全 |
| 容器 | `0.0.0.0:8080` | 容器回环外部连不进来,必须放开;固定端口便于 `-p` 映射 |

判定依据是 `/.dockerenv` 与 `/proc/1/cgroup` 里的 `docker` / `kubepods` /
`containerd` 等标记,也可用 `TVTRIM_CONTAINER=1` 或 `=0` 强制指定。
命令行显式给出的 `-addr` 永远优先。

监听在 `0.0.0.0` 时终端会多打一行提示,告诉你怎么用 `-p` 映射:

```console
  Web 界面: http://localhost:8080/
  容器模式: 容器端口 8080,用 docker -p <宿机端口>:8080 映射后访问 http://localhost:<宿机端口>/
```

### 页面打不开时怎么查

按顺序确认这四件事,基本都能定位:

1. **容器真的在监听 8080 吗** —— 看日志里的地址,必须是 `0.0.0.0:8080`,
   而不是 `127.0.0.1:...`(容器内监听回环的话,宿机端口映射永远连不进来):

   ```sh
   docker logs <容器名> | grep 'Web 界面'
   ```

   旧版本(1.4.0 及以前)在容器里默认监听回环,需要显式写 `-addr 0.0.0.0:8080`;
   `1.4.1` 起不用写了 —— 确认一下镜像标签是不是旧的。

2. **端口映射成立了吗** —— `docker ps` 的 PORTS 列应有 `0.0.0.0:8080->8080/tcp`。
   没有就说明 `-p` 没生效(写错成 `-P`、或端口被占用导致启动失败)。

3. **宿机自己能通吗** —— 先排除浏览器/网络因素:

   ```sh
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/   # 期望 200
   ```

   宿机能通但别的机器不通,那就是防火墙没放行这个端口(NAS / 云服务器上很常见)。

4. **在哪台机器上敲的 localhost** —— 要访问的是**运行 docker 的那台机器**的 IP,
   不是你正在操作的这台,也不是容器内部。

实在不行就用 `-addr` 把地址写死,它永远优先于所有默认值:

```sh
docker run --rm -p 8080:8080 -v "$PWD":/media totootao/tvtrim -web -auto -addr 0.0.0.0:8080 /media
```

## ffmpeg-trim 的获取

程序按以下优先级查找 ffmpeg:

1. `-ffmpeg` 参数指定的路径
2. `TVTRIM_FFMPEG` 环境变量
3. 缓存目录中已下载的 ffmpeg-trim
4. 自动从 `totootao/ffmpeg-trim` 下载并校验
5. `PATH` 中的 `ffmpeg`(仅当禁用下载或下载失败时兜底)

PATH 排在自动下载之后是有意的:项目指定的后端是 ffmpeg-trim,PATH 里可能是
参数语义不一致的完整版 ffmpeg。自动下载会校验文件字节数,校验失败会报错而不会
留下半截文件。缓存位置在各平台的标准用户缓存目录下,例如 Linux 是 `~/.cache/tvtrim/`。

**缓存自动升级**:缓存命中时会比对二进制字节数与内置资产清单,不一致(例如
ffmpeg-trim 从 v1 升到 v2)就删除旧缓存并重新下载。所以升级 tvtrim 后不需要
手动清缓存,下一次运行就会用上最新的 ffmpeg-trim。

### 环境变量

| 变量 | 说明 |
|---|---|
| `TVTRIM_FFMPEG` | 指定 ffmpeg 路径 |
| `TVTRIM_PROXY` | GitHub 代理前缀,默认 `https://ghproxy.totootao.top`,设为 `none` 直连 |
| `TVTRIM_CACHE_FILE` | `-auto` 识别结果的缓存文件位置,等价于 `-cache-file`(命令行优先) |
| `TVTRIM_CONTAINER` | 覆盖 `-web` 的默认监听地址:`1`/`true` 按容器处理(监听 `0.0.0.0:8080`),`0`/`false` 按宿机处理(监听回环随机端口)。不设则自动探测 `/.dockerenv` 与 `/proc/1/cgroup` |

### 测试策略:假 ffmpeg 而非 mock 接口

`internal/testkit` 提供一个按参数自动判别行为的 bash 脚本当"假 ffmpeg":

- 含 `silencedetect` → 输出预设 stderr,退出 0(silencedetect 成功)
- 含 `-ss`/`-to`/`-f` → 写出一个 >1KB 的输出文件,退出 0(stream copy 成功)
- 其余(`ffmpeg -i x`)→ 输出预设 stderr,退出 1(探测)
- `TVTRIM_FAKE_MODE=empty/fail` 可覆盖写文件行为,用于验证异常分支

之所以抽象一层接口用 mock:被测代码大量依赖子进程退出码、stderr 文本与文件副作用,
用真脚本模拟比 mock 更贴近真实行为,`-race` 下也不会掩盖并发问题。

### 项目结构

```
cmd/tvtrim/          CLI 入口:参数解析、时长格式解析、输出渲染、detect 编排
internal/ffmpeg/     二进制定位/缓存/自动下载;媒体探测(替代 ffprobe);静音检测

internal/testkit/    测试用的"假 ffmpeg"与环境辅助
```

### 一个值得记录的坑

ffmpeg-trim 是裁剪过的构建,它**会静默忽略 `-i` 之前的 `-ss`**。实测:

```sh
# 错误:片头根本没被砍掉,输出 25s
ffmpeg -ss 5 -i in.mp4 -to 25 -c copy out.mp4

# 正确:输出 20s
ffmpeg -i in.mp4 -ss 5 -to 25 -c copy out.mp4
```

完整版 ffmpeg 两种写法都正常(只是 seek 策略不同),所以这个问题只有在真机跑
ffmpeg-trim 时才会暴露。`TestBuildArgsPlacesSSAfterInput` 就是为此写的回归测试。
